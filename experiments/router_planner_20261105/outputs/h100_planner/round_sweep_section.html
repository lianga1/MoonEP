成组交换：R、K 分别花在哪一步？

这里讨论“每个 token 由 8 个线程协作”的成组交换。它的组是同一个 token 的若干专家计算任务。先固定专家驻留位置，每轮为每个 token 最多选一条搬运提议，再按相反方向、相同任务数量匹配；16 线程版与 8 线程版遵循同一规则。

N 是一层全部 token 数，本次为 134,144；K 是每 token 选中的专家数，本次为 8；R 是逻辑卡数，本次为 8；L 是交换轮数；p 是整数排序扫描数据的趟数。下面另用 Ul 表示第 l 轮真正改写执行位置的计算对数量，一个计算对就是“一个 token 交给一个专家算一次”，所以 0≤Ul≤NK。

步骤一轮工作量这个乘数从哪里来
1. 建立当前位置和可执行位置的小表O(NKR)每个 token 的 K 个专家任务，都要判断它对应 R 张卡中的哪些卡。一个 token 有 8 个专家、8 张卡时，共有 8×8 个“专家任务／卡”检查位置。
2. 选择搬运提议O(4NR²)每 token 检查 R² 个方向位置；自身到自身跳过，本次有 56 个有效有向卡对。每方向最多考虑前 1、2、4 个可搬任务和原卡上的全部任务。每个候选复用小表做整数位运算。
3. 按类别整理提议、决定接受数量O(pN + R²K)N 条记录按类别排序；计数和接受数量按“方向 × 收益 × 搬几个任务”保存。最后一项的大小范围是 1…K，因此有 K，不是每个 token 再与 K 个 token 比较。
4. 写回被接受的执行位置O(N + Ul)
上界 O(NK)		扫描 N 条提议，跳过未接受的；接受的提议搬几个任务，就改写几个位置。一个 token 最多有 K 个位置，因而最坏上界有 K。

第一步乘 R，表示检查工作量，不表示把 token 从显存重复读取 R 遍。当前 kernel 的 8 个线程先各读一个专家和执行位置，再循环检查 8 张卡。每张卡的“哪些任务现在归我”和“哪些任务我能执行”压成一个整数：每一位表示一个专家任务是否在集合中。后续方向比较复用这些整数，使用线程间交换与位运算。这样减少重复读取，但检查逻辑本身仍存在；这也不是缓存命中率或显存事务的实测结论。

第三步为什么不是只有 1、2、4 三种大小？因为还有“把原卡上的任务全部搬走”这个候选。例如某个 token 有 3 个任务在 A，且 B 都能执行，那么大小 3 的全组可以参加；5、6、7、8 也同理。因此配额表按 1…K 预留类别。本次只需给 28 对卡×8 种大小分别算数量，共 224 项；每项是固定次数的整数计算。它不做全体 token 两两比较，也不搜索“2 个任务与 1+1 个任务”的混合配对。

例如 A→B 有 100 条大小 2、收益 1 的提议，B→A 有 120 条大小 2、收益 1 的提议，直接接受双方各 100 条即可，不需要做 100×120 次比较。排序保证同一类别里按原 token 顺序选取。这里的排序只处理类别编号的 11 个二进制位，不对 token 编号逐项比较；当前 p 是固定的小常数，所以是 O(pN)，不写成比较排序的 O(N log N)。

每轮：O(NKR + 4NR² + pN + R²K + N + U_l) L 轮最坏上界：O(L · [N(KR + R² + p) + R²K]) 若把一次驻留位图准备也计入，再加 O(RE)，E=352 是专家总数。 当前 R=K=8、p 固定：O(LN)；L 也固定时：O(N)。

上述是总工作量，不是把每一步串行执行所需的时间。GPU 可以让许多 token 同时处理，但不能据此把整个式子直接除以 8。当前实现把 R、K 写死为 8，且集合装在单个整数中；不能不改实现就将此式外推到任意大的 R、K。16→8 线程改变执行效率和常数，不改变复杂度阶数。第四步实际只改 Ul 项，比直接写 NK 更能解释后几轮搬得少时的成本。

CUDA Graph 是把固定的一串 GPU 操作预先组织起来，随后整串重放，减少逐次发起的开销；普通调用则逐次发起这些操作。

计时口径：每层每个方法保留 10 次普通调用与 20 次 CUDA Graph 样本，每轮改变方法执行顺序，执行预热后计时；先取各层中位数，再对八层等权平均。通信下降按八层份数相加后计算。“交换”包含恢复起始执行位置和 L 轮交换；“起点＋交换＋输出”包含 MoonEP 语义移植版生成起点、恢复起点、L 轮交换和最终执行地址等输出，整条路径直接计时。它不是原包原生 MoonEP 的完整延迟。

排除项：两列时间均不含专家驻留选择、驻留位图打包、输入统计、编译、内存分配、正确性检查、Graph 捕获，也不含真实 token／专家权重通信或专家计算。因此目前只能据此选择规划时间与通信份数之间的取舍，不能直接宣布 L=1、2 或 4 哪个端到端更快。

核验：8 层×L=1、2、4 共 24 组结果与 CPU 对应前缀逐元素一致，L=4 与原保存结果一致；逐轮搬动数与预测收益一致，负载守恒、专家驻留合法、输出地址唯一且来源可恢复，Graph 计时前后结果均通过核验。另逐轮检查了 GPU 四轮过程的所有前缀。失败记录为空，源码与输入文件哈希保留在原始 JSON。
