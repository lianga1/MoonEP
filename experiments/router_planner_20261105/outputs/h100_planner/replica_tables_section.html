副本怎么选，之后每张卡到底扫描什么？

采样用于选择专家放在哪些卡；真正决定交换时仍检查全量 token。当前实验先在 CPU 上离线选好驻留表，再交给 GPU 成组交换。因此 H100 表中的交换延迟不包含这段副本选择。

“这张卡的 token”指原始来源卡，不是计划执行卡。一个 token 的 8 个任务即使分散到几张卡，原始来源卡保留的完整路由行仍能看到全部专家及其执行位置，由它统一提出本轮的一条交换建议。扫描的是专家编号与执行位置等元数据，不是 token 的隐藏向量。当前单卡 H100 测试把 8 份来源数据展平成一个数组；8 线程版本的八卡协调接口尚未完成八卡实测。这个分片说明仅针对当前成组交换实现，不概括原生 MoonEP 所有子 kernel。

展开：256 个样本怎样变成副本清单

先全量统计起始分配已经要求哪些专家在哪张卡执行。每卡保留自己的原属专家和这些必需副本；必需副本也占“最多 8 个额外专家”的预算。剩余槽位才参与下面的选择，不能先把已有合法执行位置删除。

从全层 134,144 行均匀、不放回地抽 256 行，每行保留全部 8 个专家及当前执行位置。对抽到的 token，把当前计划在同一张执行卡的任务合成一组。例如某行在 A 卡上的全部任务是 {e1,e2}，便考察把这一整组移到 B 是否能减少远端份数；如果所需新增副本已超过 B 的剩余预算，先剔除。每个样本、每对卡最多选择一个方向，避免把同一个样本同时当作自己的反向伙伴。

样本统计键（示意）具体专家组合样本中出现次数
A→B，大小 2，收益 1{e1,e2}12
A→B，大小 2，收益 1{e3,e4}8
B→A，大小 2，收益 0{e5,e6}10

此表是解释流程的手写示例，不是真实 trace 的统计值。收益 1 表示若该提议可执行，少一份远端 token 传输；收益 0 表示份数不变，但可以为另一方向提供等量交换。

源码的“保留 2 组”是每个完整类别：方向×大小×收益，分别保留出现最多的两种专家组合。同方向、同大小如果收益 0 和收益 1 都有候选，合起来最多有 4 组。之后把反方向、相同大小的候选组合成一个方案：B 需要补齐 A→B 组的专家，A 需要补齐 B→A 组的专家。

每次选择“新增可匹配的样本通信收益 ÷ 新增专家槽位数”最好的方案，更新两张卡的驻留表和剩余预算，再重算候选。已经存在的专家不重复收费；一个新增专家也可能同时让其他保留组合变得可用。八张卡联合选择，每卡始终不超过 8 个额外专家；没有正收益可选时结束，允许剩余槽位空着。

这里直接使用样本频数，没有乘 134,144/256 外推成全量次数。不同卡对仍可能用到重叠的样本，因此这是候选价值的估计，不是可立即提交的交换清单，也不保证全局最优。最后真正执行哪些交换，要由全量阶段重新判定。

已有三种抽样种子 20261026、20261027、20261028 的八层最终远端份数下降分别为 24.9794%、24.5005%、24.5397%。总体相差约 0.48 个百分点，但单层波动更大：第 7 层分别为 26.4472%、32.3976%、28.8764%，最大相差约 5.95 个百分点。因此不能只凭八层总数相近就断言采样稳定，也不能把三次结果当成一般精度保证或置信区间。全量交换会阻止非法执行，但不能补回采样时没有选中的专家副本。

展开：两组各含几个专家？哪些双向方案参与比较？

“保留两组”限制组合种类数，不限制每组只有两个专家。每个样本在某张计划执行卡上的完整组，可以含 1～8 个专家。大小 1、2、3……8 分别统计，收益 0、1 也分别统计，各类别保留两个组合。因此大小 3 的类别可以同时保留 {e1,e2,e3} 和 {e4,e5,e6}。

对同一卡对、同一大小，将两个方向保留的组合逐一配对，排除双方收益都是 0 的方案。不是只把第一名和第一名配对，也不是把前两名全部复制。每方向两种收益各最多两组，因此最多 4×4 个组合，排除 0+0 后每卡对、每大小最多 12 个方案。

先选第一项。本次不需要给 B 补 e3、e4；它们是另一条 A→B 备选，不是必须反向搬回的专家组。反向任务来自另一批 token 的 {e7,e8}。下一步必须重算增量：此时正向已有 40 条、反向有 30 条，再补 e3、e4 虽把正向增加到 52 条，反向仍只有 30 条，新增收益为 0，因此不选。给 A 补 e9、e10 则可再提供 8 条反向零收益提议，匹配剩余的正向正收益提议，新增收益为 8。

代码计算“假设新增副本后的可匹配收益 − 当前可匹配收益”，再除以真正缺少的副本数；比值相同优先增量更大，再优先副本更少，最后按固定方案顺序。它重算当前卡对、当前大小下的所有保留组，因为一个新专家可能补齐其他组；这仍是样本上的估计，不是全体 token 的联合最优解。

全量扫描之后的两张表

非负收益只是候选资格，不是所有候选都进入计数表。每个 token 比较全部方向和候选大小后，只提交一个最佳提议；汇总的是这些唯一提议。若该提议没有获得反向配额，本轮不再提交第二名。下一轮才重新计算。这样避免一个 token 的多条重叠提议被同时接受，但也可能漏掉原本可匹配的次优机会。

“1、2、4”各取原路由顺序下前几个可搬任务，不枚举所有同大小组合；“全部”指这个 token 当前计划在搬出卡上的全部任务，未必是全部 8 个。收益 1 优先于收益 0；同收益再按随 token 与轮次变化的大小优先级、目标卡已有任务数和方向规则选择，因而不是始终优先最大组。

每个 token 先读自己的 8 个任务，检查 56 个有效移动方向，每方向考虑前 1、2、4 个可搬任务和原卡上的全部任务，只留下一个最佳合法提议。具体专家组合的可执行性已经在这一步检查；匹配阶段只需要知道方向、任务数量和通信收益。

表一行记什么为什么需要它
token 提议表token 编号、旧卡→新卡、大小、收益，以及 move_mask：8 个二进制位标记移动哪些任务最终知道改写哪个 token 的哪几个执行位置。代码把类别和 token 编号打包存储，移动位图单独保存。
本地计数表counts[旧卡,新卡,收益,大小]只统计该类别有多少条提议，不再保存专家编号。当前分配 8×8×2×9=1,152 项；大小范围预留 0…8，部分项不使用。

八卡接口每轮汇集各卡的 1,152 个 32 位整数：一张卡的输入计数是 4,608 字节，汇集后每卡得到的计数数组是 36 KiB。这是数组大小；实际网络传输字节数和延迟取决于通信实现，不能直接等同于这两个数。

全局总数决定每类接受多少条；各来源卡之前的累计数决定这张卡的提议排在全局第几位。例如这一类全局收前 100 条，前面的来源卡已有 70 条，本卡只有前 30 条可进入。各卡内部按 token 顺序排列，所以不必把全部 token 提议表传到一张卡集中选择。

展开：等量配额的手算例子，以及“副本选择也全量做”目前实现到哪

以下是手写示例。固定 A、B 两张卡，所有提议大小均为 2；“条数”指 token 提议数量。

方向收益 1 的条数收益 0 的条数本次接受
A→B10020100 条收益 1
B→A608060 条收益 1＋40 条收益 0

双方各接受 100 条、每条搬 2 个任务，因此每个方向都搬 200 个任务，两张卡的任务总量保持不变。远端份数减少 100＋60=160。剩余可配的都是收益 0 的组合，本版不会为了零总收益继续交换。

如果希望副本选择阶段也查看全部 token，当前 CPU 函数可以把 sample_tokens 设成 N=134,144，按相同规则扫描全部数据。这会消除抽样遗漏，但仍保留每类别前 2 组和贪心选择，并不因此成为全局最优算法。这个全量副本选择的 GPU 版本、以及八卡分布式统计完整专家组合频数后再选副本的流程，目前尚未实现。

分布式实现必须先按同一专家组合正确合并全局频数，再找全局前 2 组。不能每卡只保留本地前 2 组再合并，就称为精确的全局前 2 组：某种组合可能在每卡都排第三，合计后却应当第一。现有八卡计数汇集接口解决的是固定驻留后的交换配额，不等于已经实现分布式副本选择。
