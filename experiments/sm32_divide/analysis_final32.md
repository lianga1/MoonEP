当前主要剩余耗时是驻留候选/贪心和四轮交换提议；贪心自身仍约 165 μs。选择性融合恢复了 proposal/ordinal 和较大表通信的独立 kernel，只保留实测有利的融合，因此核数量多于旧的全融合路径；判断依据是完整耗时和结果，不是 kernel 数越少越好。

不同仪器和回放边界会改变执行时间；这些差额不能按比例从各阶段扣除，也不能拿组件微基准代替完整 planner。

## 正确性、预算与传输计数

- 全部正式输出与冻结 802 原始结果逐项比较：4608 次完整 plan 九项数组哈希一致；直接 CPU oracle 核验 1136 次通过。没有 fallback。
- 重新核验 16 份预算 trace 的压缩/原始 SHA、完整回放 anchors、每次 launch 与并发线程块上限，均 ≤32，且无 NCCL kernel。这个上限不代表固定占用同一组 32 个 SM。
- 重新解析 256 份 profile trace，保留 640 次稳态回放；1280 个 event 样本与每 rank 原始文件一致。trace 最大闭合误差 0.004953 μs，event 最大误差 0.00005309 μs。
- 八层累计 token-目的卡计数：原生 5,054,165，新方案 3,887,660，下降 23.0801%；专家副本累计 434，与原结果相同。未测量权重/梯度/token payload、GEMM、优化器及完整训练净收益。

原始数据位于 `final03/evidence/`。本脚本只使用标准库、冻结 parser、CPU oracle、原结果和本次冻结 manifest；输入缺失或任何核验失败时不会生成报告。运行 `python3 recompute_final32.py` 重算。
